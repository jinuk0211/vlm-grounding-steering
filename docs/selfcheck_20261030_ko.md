## 3. POPE: Yes 로짓 임계값 baseline

모델은 그대로 두고, logit(Yes) − logit(No)가 임계값을 넘으면 "yes"로 판정합니다. 임계값은 POPE 이미지 절반에서 고르고 나머지 절반에 적용했으며, 이 분할을 50번 반복해 평균냈습니다. Gemma는 대소문자 변형("yes", "Yes" 등)을 logsumexp로 합쳤습니다. 1차 측정에서는 대문자만 써서 무효였고, 이를 고친 값입니다.

| 모델 | Base Acc / F1 | 임계값 조정 Acc / F1 | Base 대비 (분할 0 기준) | test에서 고른 상한 |
|---|---:|---:|---|---:|
| Qwen | 85.60 / 83.82 | **87.14 / 86.89** | Acc +0.4~+2.5, F1 +1.8~+4.2 | 87.40 / 87.21 |
| Gemma | 83.83 / 83.13 | 83.82 / 83.39 | 차이 없음 | 84.17 / 83.76 |

- **Qwen:** precision 95.4, recall 74.7로 "no" 쪽으로 기울어 있습니다. 임계값은 약 −1.69에서 안정적으로 수렴합니다.
- **조정 후 오류 구성:** FN은 379→212로 줄고 FP는 54→179로 늘어납니다.
- **의미:** Qwen POPE에서 무언가를 주장하려면 87.1을 넘어야 합니다.

## 4. POPE E0: "시각 쪽엔 있는데 답에서 사라지는가"

- **시각 probe.** COCO train2014 5,000장(seed 42)의 이미지 토큰을 pooling해 80클래스 로지스틱 회귀를 학습했습니다. 레이어와 pooling 방식은 train 쪽 검증 데이터로만 골랐습니다.
- **답변 위치 probe.** 답 직전 위치의 hidden state로 레이어별 선형 probe를 학습했습니다. POPE 이미지 기준 2-fold로 나눠 쓴 분석 전용 결과입니다.

| 지표 | Qwen | Gemma |
|---|---:|---:|
| 시각 probe, train 검증 AUROC | 0.985 (layer 26, mean) | 0.976 (layer 6, max) |
| 시각 probe, POPE AUROC | 0.880 | 0.859 |
| **모델 자신의 Yes−No margin, POPE AUROC** | **0.940** | **0.916** |
| probe를 그대로 답으로 쓸 때 Acc | 76.6 | 74.8 |
| probe 점수 중앙값, TP / FN | 0.88 / 0.12 | 0.64 / 0.11 |
| FN 중 probe 점수가 TP 중앙값 이상인 비율 | 13/379 | 17/303 |
| margin + probe 결합 Acc (margin 단독) | 87.18 (87.14) | 83.75 (83.80) |

**판정:** "시각 probe도 FN 물체를 읽지 못한다"는 쪽입니다.
- 모델 자신의 답이 probe보다 더 좋은 검출기입니다.
- FN은 시각 쪽 점수도 낮은, 원래 어려운 문항입니다.
- 중간층에도 출력보다 많은 정보가 남아 있지 않습니다.
- 한계: probe는 이미지 전체를 pooling한 것이라 작은 물체에는 불리할 수 있습니다.

**해석할 때 주의할 점**

- **recall은 두 모델 모두 Base보다 유의하게 떨어졌습니다.** REVIS나 GrAInS보다 덜 떨어졌을 뿐, "모든 지표에서 이겼다"고 할 수는 없습니다.
- **rollback과 삭제의 차이가 거의 없습니다.** 5절의 오프라인 삭제 추정치가 rollback 결과와 비슷합니다. 따라서 공식 채점 기준의 post-hoc 삭제 baseline을 꼭 넣어야 합니다.
- **비교 대상의 계열이 다릅니다.** REVIS, RUDDER, GrAInS, VTI는 steering 계열이고 우리 방법은 검증·디코딩 계열입니다. 같은 계열(Woodpecker, LogicCheckGPT, HALC 등)과의 비교가 아직 없습니다.
- **지연 시간은 이 표로 비교할 수 없습니다.** 테스트 실행은 GPU 1에서 4개 프로세스가 동시에 돌았습니다. 같은 조건의 비교는 7절 dev 결과를 보세요.

## 8. 내부 상태 분석 (Qwen, Base 캡션 200장, teacher forcing)

각 캡션 토큰마다 세 가지를 측정했습니다.
1. **Attention:** 그 토큰을 예측하는 위치에서 이미지 토큰으로 가는 attention 비중.
2. **이미지 기여:** 실제 이미지일 때와 같은 크기 회색 이미지일 때의 log p 차이.
3. **Jacobian 이미지 지분:** decoder 0층 입력(vision → LLM 경계)에서 log p의 gradient × input을 구한 뒤, 이미지 위치가 차지하는 비중.

**H1. 디코딩이 진행될수록 이미지 의존도가 떨어진다: 지지됨**

| 토큰 위치 | 0–15 | 32–63 | 96–127 | 192–255 | 384+ |
|---|---:|---:|---:|---:|---:|
| 이미지 attention (후반 레이어) | 0.184 | 0.140 | 0.100 | 0.062 | 0.037 |
| 실제 − 회색 log p | +1.70 | +0.54 | +0.40 | +0.19 | +0.00 |
| Jacobian 이미지 지분 | 0.70 | 0.67 | 0.49 | 0.39 | 0.18 |

한계: 캡션 후반부는 "Overall, ..."처럼 원래 이미지와 관계가 적은 문장이 많습니다. 위치와 내용이 섞여 있습니다.

**H2. 환각 물체 토큰이 맞는 물체 토큰보다 이미지를 덜 쓴다: 지지 안 됨**

| 물체 토큰에서 측정 | 환각 (90) | 정답 (947) |
|---|---:|---:|
| Jacobian 이미지 지분 | 0.727 | 0.694 |
| 실제 − 회색 log p | 1.33 | 1.45 |
| 이미지 attention | 0.169 | 0.176 |
| log p (모델 확신도) | −0.85 | −0.51 |

같은 위치 구간끼리 비교해도 차이가 없습니다. 유일한 차이는 확신도이며, AUROC 0.66입니다.

**H3. 같은 물체를 질문으로 물을 때 이미지를 더 쓴다: 지지 안 됨**

- 환각 물체(70개): 캡션 위치 0.753, 질문 위치 0.749. 그런데 질문받으면 84%를 부정합니다.
- 정답 물체(402개): 캡션 위치 0.807, 질문 위치 0.711.

**잠정 해석:** 환각 물체는 "이미지를 안 봐서" 생기는 게 아닙니다. 이미지를 보고 함께 나올 법한 물체를 추측한 것이고, 질문을 받을 때만 존재를 검증하는 계산이 일어나는 것으로 보입니다. 단, 근거에는 세 가지 한계가 있습니다.
- 환각 표본이 90개뿐입니다.
- attribution 측정이 한 종류입니다.
- Gemma 재현은 중단됐습니다.

## 9. 아직 확인되지 않았거나 약한 부분

1. **선행연구.** 같은 아이디어를 다룬 논문이 있다는 지적을 받았지만 아직 검증하지 않았습니다. "캡션 물체를 같은 모델에 Yes/No로 재질의해서 삭제하는 IJCAI 2026 논문"과 Self-Validation Framework가 그 대상입니다. Woodpecker와 LogicCheckGPT 계열과의 차별점도 정리되지 않았습니다.
2. **post-hoc 삭제 baseline 공식 채점.** 실제 텍스트를 수정해 공식 CHAIR로 채점한 결과가 없습니다.
3. **같은 계열 baseline.** Woodpecker, LogicCheckGPT, HALC 등과 비교하지 않았습니다.
4. **지연 시간.** 단독 GPU에서 Base 대비 배율을 정확히 재지 않았습니다.
5. **WordNet 버전.** 테스트 500장, Gemma, AMBER, MMHal 결과가 없습니다.
6. **H2/H3.** 표본을 늘리고 attribution 방법을 2–3종으로 넓혀야 합니다(attention knockout, activation patching 등). Gemma 재현도 필요합니다.
7. **AMBER와 MMHal.** 둘 다 Base 답변 생성 도중에 중단했습니다.
   - AMBER는 평가에 spaCy와 `en_core_web_lg` 설치가 필요한데, 아직 설치하지 않았습니다.
   - MMHal은 gpt-4o judge와 API key가 필요합니다.
